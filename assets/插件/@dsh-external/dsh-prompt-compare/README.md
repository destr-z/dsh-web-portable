# @dsh-external/dsh-prompt-compare

**提示词对照工作台**：把**剧本**（锚点侧，只读）和**视频提示词**（作业侧）按集并排放，
人工逐块对照、在提示词上划词写批注，批注整理成指令交给 agent 改稿，产出下一版。

设计依据：`docs/执行设计-v1.md`（目录结构、清单格式、两个工具的行为、错误显示、代码去留）。
姊妹插件：`dsh-novel-script`（剧本批注）——**两者刻意同构**，见下文 §6。

**只改提示词。剧本是只读参考，一个字都不动。**

> ⚠️ **样式类前缀是 `pc-`，不要改回 `ns-`。** 姊妹插件 `dsh-novel-script` 用的是 `ns-`，
> 而两个面板**会同时出现在同一个页面里**、各自插一个 `<style>`，同名类**后注入的赢**。
> 2026-09-15 踩过一次：两边都叫 `ns-para`，而本插件那边是 `flex-direction: column`
> （块要抬头一行、正文一行），结果把剧本批注面板的段落整个竖排了。
> 加样式前先看一眼对方有没有同名类。

## 1. 分工（一句话）

**程序只读写一个固定目录：算行号、校验、把批注存回去；版本怎么建、块怎么切、对应哪几行，全由 agent 用普通文件操作 + 工具做。**

程序做五件事（设计文档 §10.1）：

1. 读 `对照工作台/`：按集配对剧本 / 提示词 / 清单 / 批注；
2. 写提示词 + 清单（算行号、校验，**两个一起写**）；
3. 刷清单（按 anchor 定位）；
4. 批注读写（宿主侧合并）；
5. 按清单里的行号做高亮。

程序**不**做（§10.2）：**不解析正文格式**（不认 `Block N`、不认 `@标记`、不认字段名）、
不判断剧情/措辞/对错、不算覆盖率、不做告警面板、不为"文件被手工改过"兜底、**不改剧本**。

> 对齐由 **agent 判定**：剧本场次与提示词块数**不是**一一对应（全剧 89 场 vs 115 块，
> 只有 11/35 集两者相等），所以程序不做任何"按场景标题切分"的推断（§4.4）。

## 2. 目录结构（工作区里，固定位置）

```
<工作区根>/
  对照工作台/
    剧本/
      第1集剧本.txt          ← 锚点侧：只读参考，不随版本变（agent 从合集拆出来）
      第3集剧本.txt
    v1/
      提示词/
        第1集提示词.txt        ← 作业侧（随版本走）
      清单/
        第1集清单.txt          ← 工具写：块 → 剧本行号
      批注/
        第1集批注.txt          ← 界面写（宿主侧合并落盘）
      变更记录.txt             ← agent 写（可选）
    v2/
      …
```

三条硬约定（与剧本批注同源，§3）：

1. 工作台固定在 `<工作区根>/对照工作台/`，没有任何设置项；
2. **剧本在根下、不随版本变**；版本只包住**提示词 + 清单 + 批注**；
3. 文件名一律**阿拉伯数字、不补零**：`第3集剧本.txt`、`第3集提示词.txt`（程序不解析中文数字）。

**输入形态由 agent 归一**：用户给的剧本/提示词可能是全集一份、每集一份、几集合一份；
agent 拆成"每集一份"后自检行数。程序只认固定目录 + 固定文件名。

### 剧本文件里放什么（§4.1）

`剧本/第N集剧本.txt` = 合集里该集小节的**全文**，只做两件机械清理：
去掉 markdown 围栏行、去掉末尾空行与集间分隔线。**`## 标题` / 人物表 / `### 正片剧本` 标题都保留**
（提示词里到处是 `@江瑶_5岁` 这类带状态的标记，人物表在旁边对照时直接能看）。
约定：标题与人物表**不需要高亮、也不该被 `scriptRanges` 引用**；引用了**不阻断**（§5.2 只校验行号越界）。

## 3. 两个工具

### 3.1 `prompt_compare_write_episode`（整集重写）

```jsonc
{
  "version": "v1",                          // /^v\d+$/
  "episode": 1,                             // 正整数
  "header": "《…》第 1 集 视频提示词｜…",      // 可选；文件头，占第 1 行
  "blocks": [
    { "text": "── Block 1 | 14s ──\n场景：…\n\n生成信息：…", "scriptRanges": [[1, 25]] },
    { "text": "── Block 2 | 20s ──\n…",                     "scriptRanges": null }
  ]
}
```

- 拼文件：`header` + 一个空行 + 块1 + 一个空行 + 块2 + …；**末尾有且只有一个换行**（§4.2）；
- **块内空行原样保留**（实测 115/115 块每块恰好 4 个块内空行），只有**块首尾**不允许空行；
- `promptLines` 由工具算（含块内空行、不含块间空行、`header` 计入偏移），agent 不填；
- **两个文件一起写**；任何一条不合法 → **两个都不写**；
- 返回 `{ ok, episode, blocks, promptLines: [[起,止], …], scriptLines, warnings }`。

### 3.2 `prompt_compare_write_manifest`（只刷清单）

```jsonc
{
  "version": "v1",
  "episode": 1,
  "blocks": [
    { "anchor": "── Block 1 | 14s ──", "scriptRanges": [[1, 25]] },
    { "anchor": "── Block 2 | 20s ──", "scriptRanges": null }
  ]
}
```

- 读**已存在**的 `v1/提示词/第N集提示词.txt`（不存在 → 报错，不凭空造一份）；
- 从头**顺序**为每个 anchor 找**唯一命中**（第 k 个只在前一个块结束之后找）；
  每块结束行 = 下一个 anchor 行之前**最后一个非空行**（最后一块算到文件末尾最后一个非空行）；
- **只写清单**，一个字节都不碰提示词与剧本；
- **未命中 / 命中多次 → 报错**，错误里带 **anchor 原文 + 命中行号**，让 agent 自己换成更长的 anchor。
  **不猜、不降级**；
- 用途：**首次入库**（提示词已在，agent 只需给"首行 + 剧本行号"，不必复述正文）、
  以及就地微改正文之后补刷清单。

### 3.3 纪律：改提示词必须同步清单

提示词和清单是一对，只改一边工作台就错位。两条路选一条：

- 整集重写 → 用 `write_episode`（两个文件一起写）；
- 只改了提示词（或提示词本来就在）→ 改完**补一次** `write_manifest`。

## 4. 清单格式与校验

```json
{
  "schema": 1,
  "blocks": [
    { "anchor": "── Block 1 | 14s ──", "promptLines": [3, 22], "scriptRanges": [[13, 36]] },
    { "anchor": "── Block 2 | 20s ──", "promptLines": [24, 44], "scriptRanges": [[38, 77]] }
  ]
}
```

| 字段 | 谁给 | 含义 |
|---|---|---|
| `schema` | 程序 | 固定 `1`；不认识就拒绝读（不猜） |
| `blocks[]` | — | 按**文件顺序**；下标 + 1 = **位置序号**（批注锚点就是它） |
| `anchor` | agent（入库时）/ 程序（整集重写时） | 块**首行**文本，只用于定位 |
| `promptLines` | **程序算** | 该块在提示词文件里的行号区间（1 基、闭区间） |
| `scriptRanges` | agent 判断 | 该块覆盖剧本哪几行；`null` = 剧本里没有对应（本身就是个值得看的情况） |

**块的标识用位置序号，不用正文里的 `Block N`**（§4.3）：实测第 6 集正文是 `1, 4, 5`（跳号，手工改过的痕迹），
拿正文号码当 ID 会让批注锚点错位。位置序号对跳号、改号、换套命名法全都免疫。

写入前的硬约束（§5.2，一条不满足就**不写任何文件**）：

1. `version` 匹配 `/^v\d+$/`、`episode` 是正整数；
2. `blocks` 非空数组；
3. 每块正文非空、**首尾无空行**（内部空行随便）；
4. 每个 `scriptRanges` 要么 `null`，要么非空数组，每项 `1 ≤ a ≤ b ≤ 本集剧本行数`；
5. **剧本文件必须存在**（没有它算不出上界，也说明工作台没摆好）；
6. `anchor` 在提示词里**唯一命中**，且各 anchor **按文件顺序**出现。

**自检信息（`warnings`）**：返回给 agent、不上面板、**不阻断写入**（§5.3）——
某块 `scriptRanges` 为 `null`、起始行**回退**、相邻块**有重叠**。

## 5. 批注流程与通道

- 格式与剧本批注**完全相同**：`id / regions[] / problem / done / resolvedIn`，
  **没有剧本上下文字段**（agent 需要剧本时自己按清单去读）；
- `regions[].paragraph` = **块的位置序号**；跨块连续选择时记 `endParagraph`；`quote` 是选中的提示词原文；
- 通道：`POST /api/prompt-compare/annotations`，`op: 'load' | 'save'`；
- 走的是 **Connection 的 exact Fetch route**（`/api` 载体自带 Host/Origin 校验与浏览器认证）。
  **不用 Typert Remote**：那条路要生成式 zod 清单（40 KB 级、由生成器产出），本插件的离线构建跑不了生成器；
- 合并策略在**宿主侧**一次完成：**磁盘上的 `done` / `resolvedIn` 优先**，界面只负责把新批注并进去；
  - 文件**不存在** → 返回 `[]`（当空数组，不是错误）；
  - 文件存在但 JSON 坏 / 字段非法 → **拒绝写，不覆盖**（宁可不保存，也不丢用户已写的问题）；
- 浏览器调用**没有** `exec.agent.session`，只能靠 `sessionId` 找会话；找不到就报错，
  **不退回部署默认策略硬写**（那会写到 DSH 服务进程目录里去）。

「下发」按钮把批注整理成指令粘给 agent，指令里带**三个路径**（清单 / 提示词 / 剧本）
但**不带剧本原文**，并明确要求改完调 `prompt_compare_write_episode` 重写这一集、
再把对应批注的 `done` / `resolvedIn` 勾上。

## 6. 与「剧本批注」（`dsh-novel-script`）的关系

同一个工作台的**镜像**，只是"哪边是锚点、哪边是作业区"换了个方向：

| | 剧本批注 | 本插件 |
|---|---|---|
| 左栏（锚点侧，只读） | 小说原文 | **剧本**（每集一份） |
| 中栏（作业侧，可划词） | 剧本 | **提示词** |
| 清单内容 | 剧本段落 → 原文行号 | **提示词块 → 剧本行号** |
| 工具 | `novel_script_write_episode` | `prompt_compare_write_episode` + `prompt_compare_write_manifest` |
| 批注通道 | `/api/novel-script/annotations` | `/api/prompt-compare/annotations` |

**同构是为了将来"合并成一个插件"或"抽共享内核"都只是机械操作。改动时两边一起改**（§1）。
两边**唯一的规则差异**：块内**允许**空行（§4.2，实测逼出来的，不是设计偏好）。

## 7. 已知边界

1. **原子性是"先全部校验、再写"**，不是事务：任何一条不合法都在**写第一个字节之前**抛错，
   所以"半成品文件"不会出现；但两次写入之间若发生系统级失败（磁盘满、进程被杀），
   **没有回滚** —— 此时提示词已是新的、清单还是旧的，用 `write_manifest` 补一次即可。
2. **不做"清单过期"检测**：程序不记时间戳、不比文件新旧。改了提示词忘了刷清单，
   界面只会按旧 `promptLines` 显示（可能错位），得靠 agent 按纪律补齐。
3. **anchor 撞车**：太短或太通用的行（重复出现的分节标题、`THE END` 之类）在整份文件里多处命中时会定位失败并报错。
   这是**故意的** —— 换成更长的 anchor 就好，程序不猜哪一处才对。
4. **行号口径以 `splitLines` 为准**（`\r\n`/`\r` 先归一成 `\n`，再按 `\n` 切，下标 + 1 = 行号）。
   `scriptLines` / `promptLines` / anchor 定位三处共用同一把尺子。
   唯一的例外是**行数**：`scriptLines`（返回给 agent 的越界上界）取**内容行数** ——
   文件末尾带的那个换行会被 `splitLines` 多切出一个空串，不减去它越界校验就会松一格
   （第 1 集实际 205 行，却会放行 `[[1,206]]`）。
5. **不校验"引用得对不对"**：`scriptRanges` 只校验行号存在、不越界；
   引用了标题行/人物表、或两块引用同一段剧本，都**合法**（最多进 `warnings`）。
6. **中文数字不支持**：集号一律阿拉伯数字，`第三集` 这种文件名程序不认。

## 8. 实现要点（改这个插件之前先看这段）

1. **宿主写文件必须带会话沙箱策略**（踩过两次）：目标目录取调用方会话的 `header.cwd`，
   策略取 `sandboxPolicy.resolve({ session })`，并把它作为 `writeText` 的**第 5 个参数**。
   不带策略 → 退回部署默认策略（根是 DSH 服务进程目录）→ 写工作区一律被拒。
2. **路径一律工作区相对、正斜杠**，只用 `src/shared/protocol.ts` 里的路径函数拼。
   不要写 `../提示词/…`：`fs.resolve` 的基准是会话工作区，多一层相对换算就多一处出错。
3. **行号与定位的口径只在 `src/shared/validate.ts` 里实现一次**，宿主不要再复算一遍
   （`buildPromptText` 一处算行号、`computePromptLinesByAnchors` 一处做锚点定位）。
   复算的代价是两边口径会漂，而"清单/界面/批注锚点三方对不上"是最难查的一类 bug。
4. **`protocol.ts` 是唯一真相源**：目录名、文件名正则、`schema` 版本、批注结构都从它来。
5. **浏览器侧读文件是分页的**：`workspaceFiles.read` 一次只给一页（默认 5000 行），
   超出只回 `eof: false`，不报错也不提示 —— 必须自动翻页读完（`src/client/workspace.ts` 已处理）。
6. **错误一律"读不懂就报出来，不猜、不降级"**：抛错好过写半份、猜一个好过静默错位。

## 9. 构建与安装

```powershell
cd D:\001\ai\deepseek\dsh-plugins\dsh-prompt-compare
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1
```

完全离线：`tsc`（host）与 `tsdown`（client）都用 checkout 里现成的副本，不下载任何东西；
脚本会校验 client 产物的装载协议（`__ModuleLoader__`、react 是否被误打进 bundle 等）。

profile（`~/.dsh/profiles/web/package.json`）里已用 `link:` 指向本目录并登记在
`dsh.profile.bundles`；`node_modules\@dsh-external\dsh-prompt-compare` 是指过来的 junction。

| 改了什么 | 要做什么 |
|---|---|
| `src/client/**` | 跑一次构建 → **刷新浏览器** |
| `src/index.ts` / `src/shared/**`（宿主半边） | 跑一次构建 → **重启 `dsh web`** |
